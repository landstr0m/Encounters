# Project context for future sessions

**What this is:** Andrew's D&D 5e (2024 rules) encounter tracker for his in-person Blackrock campaign (west-marches style: different players and characters each session, one-shot sessions, 6ish players at levels 1–3). Combat runs on an iPad or laptop; phones are only for building encounters. Dice are rolled physically at the table, so the app never rolls attacks or damage (only optional monster HP/initiative).

**Long-term direction:** this started as a project to learn MCP. The tracker is stage 1; later stages (MCP server, voice input, Kanka reports, lights/music) are in `ROADMAP.md`. **Start with the "Next steps" list at the top of `ROADMAP.md`.**

Open design points for Andrew are in `DESIGN.md`. Before that (13 Nov): play test 1 done; follow-ups are at the top of `ROADMAP.md` (remote session live on Supabase and confirmed on two devices; combat sizing, equipment reference and consumables done; named poisons, encounter generator (packs, twists, lock, rescale), monster namer, Defeat / Fled and the end-of-combat summary added; next: check D&D Beyond items with a real sheet, repeat table test). ## Conventions
- **Structure (changed 14 Nov 2026, see `DESIGN.md`):** `index.html` is only the page shell; styles are in `app.css`; the program is twelve files in `js/` (`boot.js` loads `monsters.json`, then the eleven parts in order; code map at the top of `js/boot.js`). Still no build step, no frameworks, no modules: everything is global, the parts are one program cut into readable files. A constant must be defined in the same or an earlier part than code that uses it while loading. A new file goes into `PARTS` (`js/boot.js`), `FILES` (`sw.js`) and the README table.
- **Formatting:** Prettier (`.prettierrc`, 140 columns) for `js/`, `app.css`, `sw.js`. After editing run `npx prettier --write .` (the Tests workflow checks it). One statement per line keeps GitHub diffs readable; do not go back to packed lines.
- **Workflow:** Claude pushes straight to `main`; Andrew reviews on GitHub and tests on the iPad. For quick local edits he pulls and runs `python -m http.server 8000`.
- **Every change:** run `python tests/run_tests.py` (parallel workers; `-j1` runs one at a time; all must pass), add a test for new features, bump `CACHE` in `sw.js`, log bugs in `BUGS.md`, tick goals in `ROADMAP.md`, keep `README.md` usage instructions current.
- **Data changes:** run `python tools/check_monsters.py` after editing `monsters.json`; it should report only known items. `python tools/appendix_b.py` works on `local/my-books.json` (habitats, older names, CR and type cross-check from lists pasted into `local/`).
- **Shared terms** live at the top of `js/rules.js` (`AK` / `AB` / `ABS` abilities, `DEFK` defence lists, `NOSAVE`); use them instead of new literal lists. `clone()` for deep copies. `class="grow"` instead of `style="flex:1"`.
- **Replies to Andrew:** short. He has a limited token budget. Ask before design choices that aren't obvious.
- **Visual changes:** keep colours in the `:root` tokens (light = parchment, dark = dark dungeon). `visibility_core_controls` (phone / iPad / laptop × light / dark: core controls on screen and not covered, WCAG 4.5:1 text contrast) and `icon_alignment` must pass.
- **Rules wording:** use 2024 (SRD 5.2) terms and condition names. Monsters, conditions and encounter budgets are always 2024; only player spells and half-caster slots follow the edition switch.

## Data and licensing (important)
- `monsters.json` is SRD 5.2 only (CC-BY-4.0, 341 stat blocks). Anything that is not open content never goes in the repo: it lives in the git-ignored `local/` folder and reaches the app as a file added on the device (Data → Sources → Your files; `readMonFile()`, `CUSTOM`, `mergeMon()`). Such a file can hold `monsters`, `spells` and `aliases`. It can also be added by link (`readMonLink()` → `readMonText()`, `linkUrl()` turns Drive / Dropbox share links into readable ones; the stored file keeps `url` and, for Drive, `key`; both are private like `S.hook`). Built-in ids stay as they are (`mm-…`) so saved encounters keep working.
- `reference.json` is SRD 5.2 only and `reference-2014.json` SRD 5.1 only (both CC-BY-4.0). Spells from your files are merged in `refLoad()`.
- Tests marked `@own_file` need `local/my-books.json` (Andrew's private file) and are skipped without it, so the battery passes on GitHub; `own_file_end_to_end` covers adding the file through the app.
- `dndbeyond.json` is written by the D&D Beyond Action from `dndbeyond.txt` (public sheets only, no login). Status names: internal keys stay fixed for saved data; shown names are in `NAME` (in `js/`).
- `players.json` is written by the Kanka GitHub Action (secret `KANKA_API_KEY`). Kanka may not stay the main source, so treat the party library as source-independent.

## Where things are
- Data tab: `DSEC` (sections), `S.dsec` (current), `dataHTML()` → `dataEncHTML()` / `dataSessHTML()` / `dataSrcHTML()` / `dataBakHTML()`, each built from `dcard(title, hint, body)`. Jump there with `openData('sess')`, never by setting `S.tab` by hand. Tests set `S.dsec` before looking for a control.
- Rules edition: `S.pcEd` (default, Data → Sources), `l.ed` (one character), `pcEd(l)`; `spRef(name, ed)` returns the SRD 5.1 spell from `REF.by14` (`reference-2014.json`, built by `tools/build_reference.py …/srd-2014`) or the 2024 one; `spellData()` reads either wording (`capConds`, cantrip / ray patterns); `pcSlots()` has the 2014 half-caster rule. Monster `aka` (2014 names) and `hab` come from `tools/appendix_b.py`.
- State: `S` (saved, exported) and `ui` (screen only). `fixIds()` repairs loaded state (containers, broken rows, ids). `save()` persists; `renderBoard()` / `renderDrawer()` redraw.
- Buttons: `data-act="..."` handled by one click listener per area (search `act==='name'`).
- Status mechanics: `SPELLS` table and `EXP` (auto-expiry) (in `js/`); status wording in `statuses.js`.
- Undo: `snap(label)` before a change.
- Monster actions: `actsOf(m)` parses (cached) via `parseAct()`; cards use `tcCard()` (turn card) and `one()` in `statHTML()`. After parser changes run `python tools/check_actions.py`.
- Tap-to-use: `actStart()` / `actBegin()` start targeting (`ui.act`), `actRows()` draws the chips, `actApply()` applies per target, `doHow()` spends the use (no own snapshot inside an apply). Per-creature state: `c.ue` (this turn), `c.mu` (Multiattack pools), `c.ray`, `c.mrep`, `c.uses` / `c.spent` (per encounter), `c.la` / `c.lonce` (legendary), `c.gb` (grappled by).
- Spells: `spellData(name, {dc, sat})` from `REF` (needs `refLoad()`); players' DC from `pcDCs()` (Kanka or D&D Beyond `parsed` class list).
- Log and table line: `logAdd()` (only while combat runs), `S.logs`; `annSet()` / `S.ann` shown by `renderAnn()` in table view.
- Consumables: `REF.items` (SRD equipment from `build_reference.py`), `ITEMFX` (tap-to-use effects by item name), `itemData()` builds the same shape as `spellData()` for `actBegin()`; `pcItemsHTML()` on the player turn card; carried items come from `l.items` (D&D Beyond).
- Encounter generator: `genRoll()` (uses `XPB`, `CRXP`, options in `S.gen`), `GENV` environments (`genFits()`: a monster's `hab` list decides for habitats, `any` = everywhere on land, empty = Other planes; keyword rules for sites `GSITE` and for monsters without a list; `GENVOLD` renames saved keys), `genHTML()` in the Data tab. Monster namer: `S.namer`, `ADJ`, `adjName()` inside `addMon()`. Extras: `GPACK` theme packs, `TWISTS`, locked items passed to `genRoll(keep)`, `S.seen` (no repeats), `genList()` + Save to library, `S.genLast` / `genDrift()` / `genRescale()`, `S.quirk` / `quirkLine()` (`c.q`). Fled: `c.fled` + `c.fhp` with HP 0 (so every "defeated" check still works). End of combat: `endSummary()` → `S.endSum` and `S.loot`. Treasure: `lootBuild(value, consumables)` (diamonds, `GEMS`, `ARTS`), `lootSplit()`, `lootText()`, `discordSend()` using `S.hook` (a Discord webhook URL: a secret, lives in saved state only, never in the repo or `tableSnap()`).
- Remote session: `S.sess` (code, toggles, player keys), `tableSnap()` is the only thing sent to other devices (whitelist: add fields there on purpose), `netReq()` applies player requests without `snap()`. `session.json` holds the public Supabase URL + publishable key; `?net=local` swaps in BroadcastChannel for tests.
- Tests add `window.__e` in the test browser to evaluate code in the page, and wait for `window.STARTED` (see `tests/run_tests.py`).
